## uptime
---
```sh
root@lima-default:~# uptime
 16:33:22 up 1 min,  1 user,  load average: 0.05, 0.02, 0.00
```

리눅스 및 유닉스 계열 운영체제에서 `uptime` 명령어는 시스템이 부팅된 이후 얼마나 오랫동안 켜져 있었는지(가동 시간)를 확인하는 명령어이다. 이와 함께 현재 로그인한 사용자 수와 시스템의 부하 평균(Load Average) 정보도 제공한다. 서버의 작동 상태나 갑작스러운 재부팅 여부를 간단히 점검할 때 매우 유용하게 쓰인다.
### 주요 출력 정보
터미널에 `uptime` 을 입력하면 다음과 같은 형태의 결과가 한 줄로 출력된다:
- 현재 시간: 시스템의 현재 시각 (`16:33:22`)
- 가동 시간: 시스템이 재부팅 없이 연속으로 작동한 기간입니다 (`up 1 min`)
- 사용자 수: 현재 시스템에 로그인되어 있는 사용자 계정의 수입니다 (`1 users`)
- 부하 평균: 최근 1분, 5분, 15분 동안의 시스템 평균 부하율(Load Average) (`0.05, 0.02, 0.00`)
	- 이 값이 CPU 코어 수보다 높으면 시스템이 과부하 상태임을 의미

### 자주 사용하는 명령어 옵션
- `uptime -p` (Pretty): 가동 시간만 사람이 읽기 편한 포맷(예: up 2 weeks, 1 day, 3 hours)으로 요약하여 보여준다.
- `uptime -s` (Since): 시스템이 마지막으로 부팅된 정확한 날짜와 시간을 출력한다.

## top
---
```sh
root@lima-default:~# top
top - 16:33:22 up 1 min,  1 user,  load average: 0.04, 0.03, 0.00
Tasks: 130 total,   1 running, 128 sleeping,   0 stopped,   1 zombie
%Cpu(s):  0.1 us,  0.1 sy,  0.0 ni, 99.8 id,  0.0 wa,  0.0 hi,  0.0 si,  0.0 st
MiB Mem :   3899.1 total,   1917.0 free,    442.9 used,   1702.0 buff/cache
MiB Swap:      0.0 total,      0.0 free,      0.0 used.   3456.3 avail Mem

    PID USER      PR  NI    VIRT    RES    SHR S  %CPU  %MEM     TIME+ COMMAND
      1 root      20   0   25316  14792  10200 S   0.0   0.4   0:01.99 systemd
      2 root      20   0       0      0      0 S   0.0   0.0   0:00.00 kthreadd
      3 root      20   0       0      0      0 S   0.0   0.0   0:00.00 pool_workqueue_release
```

`top` 명령어는 리눅스 및 유닉스 계열 시스템에서 실시간으로 CPU 사용량, 메모리 사용량, 실행 중인 프로세스 목록 등 시스템의 전반적인 성능 상태를 모니터링하는 도구이다. 윈도우 운영체제의 '작업 관리자'와 유사한 역할을 하며, 시스템 부하나 리소스 소모 원인을 진단할 때 가장 기본적으로 사용된다.

### 화면 구성 및 주요 정보
명령어 실행 시 화면은 크게 상단의 시스템 요약 정보와 하단의 프로세스 상세 목록으로 나뉜다.

#### 시스템 요약 정보
- **`uptime` / `load average`**: 시스템 가동 시간 및 1분, 5분, 15분간의 평균 시스템 부하율
- **`Tasks`**: 현재 실행 중(running), 대기 중(sleeping), 정지된(stopped), 좀비(zombie) 상태인 프로세스의 총 개수
- **`%Cpu(s)`**: 사용자가 사용하는 영역(us), 시스템이 사용하는 영역(sy), 유휴 상태(id), 대기 상태(wa) 등의 CPU 사용률 세부 지표
    - `us` (user): 일반 사용자 앱이 사용하는 CPU 비율
    - `sy` (system): 리눅스 커널 등 시스템이 사용하는 CPU 비율
    - `ni` (nice): 우선순위가 낮게 설정된 앱이 사용하는 CPU 비율
    - `id` (idle): 아무 일도 하지 않고 쉬고 있는 CPU 비율
    - `wa` (iowait): 디스크 하드웨어 반응을 기다리며 멈춘 CPU 비율
    - `hi` (hardware irq): 하드웨어 인터럽트 처리에 소모되는 CPU 비율
    - `si` (software irq): 소프트웨어 인터럽트 처리에 소모되는 CPU 비율
    - `st` (steal time): 하이퍼바이저가 가상 머신에서 빼앗아 간 CPU 비율
- **`MiB Mem` / `MiB Swap`**: 전체, 여유, 사용 중인 물리 메모리(RAM) 및 스왑(Swap) 메모리 용량
    - `total`: 장착된 전체 물리 또는 스왑 메모리 용량
    - `free`: 현재 완전히 비어 있는 순수 여유 메모리 용량
    - `used`: 현재 프로그램들이 직접 차지하고 있는 메모리 용량
    - `buff/cache`: 디스크 속도를 높이기 위해 임시로 데이터를 선점해 둔 용량
    - `avail Mem`: 새 프로세스가 즉시 가져다 쓸 수 있는 실질적인 여유 용량

#### 프로세스 상세 목록 (하단 컬럼)
- `PID`: 프로세스 고유 식별 번호
- `USER`: 프로세스를 실행한 사용자 계정
- `PR`: 커널이 관리하는 프로세스의 실제 스케줄링 우선순위
- `NI`: 사용자가 조절할 수 있는 우선순위 값 (-20 ~ 19, 낮을수록 우선순위가 높음)
- `VIRT`: 프로세스에 할당된 전체 가상 메모리 크기 (실제 RAM + 스왑 + 예약 공간 포함)
- `RES`: 프로세스가 실제 물리 RAM을 차지하고 있는 메모리 크기 (가장 눈여겨봐야 할 수치)
- `SHR`: 다른 프로세스와 공유하고 있는 메모리 크기
- `S`: 프로세스의 현재 상태 (`R`: 실행 중, `S`: 대기 중, `Z`: 좀비 등)
- `%CPU`: 해당 프로세스가 사용 중인 CPU 비율
- `%MEM`: 해당 프로세스가 사용 중인 물리 메모리(RES)의 비율
- `TIME+`: 프로세스가 시작된 이후 총 CPU를 사용한 누적 시간
- `COMMAND`: 프로세스를 실행한 명령어 명칭

### 실행 중 자주 쓰는 단축키
`top` 명령어가 실행된 상태에서 키보드를 누르면 실시간으로 정렬이나 화면 출력을 변경할 수 있다.
- `P`: CPU 사용량 높은 순으로 프로세스 정렬
- `M`: 메모리 사용량 높은 순으로 프로세스 정렬
- `1`: CPU 코어별 사용량을 개별적으로 확장하여 표시
- `k`: 특정 프로세스 종료 (PID를 입력하여 kill 시그널 전달)
- `q`: top 모니터링 화면 종료 후 터미널로 복귀

리눅스 시스템 관리를 더 시각적이고 직관적으로 하고 싶다면, `top` 을 개선하여 컬러 그래프와 마우스 클릭을 지원하는 `htop` 을 설치하여 사용하자.

## vmstat
---
```sh
root@lima-default:~# vmstat
procs -----------memory---------- ---swap-- -----io---- -system-- -------cpu-------
 r  b   swpd   free   buff  cache   si   so    bi    bo   in   cs us sy id wa st gu
 1  0      0 1964672  30004 1714180    0    0   409   582  196    0  0  0 99  0  0  0
```

`vmstat` (Virtual Memory Statistics) 명령어는 시스템의 프로세스, 메모리, 스왑, 입출력(I/O), CPU 활동 상태를 요약하여 보여주는 리눅스 모니터링 도구이다. 실시간 변화를 추적하는 `top`과 달리, 지정된 주기에 따라 시스템 리소스의 전반적인 통계와 흐름을 한눈에 파악하고 병목 현상을 진단하는 데 주로 사용된다.

### `procs` (프로세스 상태)
- `r` (runnable): CPU 자원을 할당받기 위해 실행 대기열에서 기다리고 있는 프로세스의 수
	- 이 수치가 CPU 코어 수보다 지속적으로 크면 CPU 병목을 의미
- `b` (blocked): 디스크 입출력(I/O)이나 네트워크 등 자원 처리가 끝나기를 기다리며 멈춰 있는 프로세스의 수

### `memory` (물리 메모리 상태)
- `swpd`: 디스크의 가상 메모리(스왑 공간)로 이동되어 사용 중인 메모리의 양 (단위: KB)
- `free`: 현재 아무 용도로도 사용되지 않고 완전히 비어 있는 여유 메모리의 양 (단위: KB)
- `buff`: 디스크 장치의 블록 데이터를 임시로 저장하는 버퍼 메모리의 양 (단위: KB)
- `cache`: 읽었던 파일 데이터를 재사용하기 위해 임시로 저장하는 캐시 메모리의 양 (단위: KB)

### `swap` (스왑 메모리 활동)
- `si` (swap-in): 디스크(스왑)에서 물리 메모리(RAM)로 매초 읽어 들이는 메모리의 양 (단위: KB)
- `so` (swap-out): 물리 메모리(RAM)가 부족하여 디스크(스왑)로 매초 밀어내는 메모리의 양
	- 이 수치가 지속해서 발생하면 RAM 증설이 필요

### `io` (디스크 입출력 활동)
- `bi` (blocks received): 디스크 등의 블록 장치로부터 매초 읽어 들인 블록의 수 (디스크 읽기 동작)
- `bo` (blocks sent): 디스크 등의 블록 장치로 매초 내보낸 블록의 수 (디스크 쓰기 동작)

### `system` (커널 및 시스템 활동)
- `in` (interrupts): 매초 발생하는 하드웨어 및 소프트웨어 인터럽트의 횟수
- `cs` (context switches): CPU가 실행할 프로세스를 교체하는 매초 동작 횟수
	- 이 수치가 과도하게 높으면 시스템 부하가 커짐

### `cpu` (CPU 자원 사용률)
- `us` (user): 커널 코드를 제외한 일반 사용자 앱 및 프로그램이 소비 중인 CPU 시간의 비율 (%)
- `sy` (system): 리눅스 커널 코드 및 시스템 자체 프로세스가 소비 중인 CPU 시간의 비율 (%)
- `id` (idle): 아무 일도 하지 않고 쉬고 있는 비어 있는 CPU 시간의 비율 (%)
- `wa` (iowait): 디스크 입출력(I/O) 작업 완료를 기다리며 멈춰 있는 CPU 시간의 비율 (%)
- `st` (steal): 가상화 환경(VM)에서 다른 가상 머신에 자원을 빼앗겨 대기한 CPU 시간의 비율 (%)
- `gu` (guest): 가상 머신(가상 CPU)을 실행하는 데 소비한 CPU 시간의 비율 (%)
