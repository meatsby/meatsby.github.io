## minikube, kind, multipass, lima 비교
---
### minikube
- 로컬에서 쿠버네티스(Kubernetes) 클러스터를 쉽게 실행할 수 있게 해주는 도구
- 다양한 드라이버 지원(Docker, VirtualBox, Hyperkit, KVM 등)
- 쿠버네티스 학습, 개발, 테스트에 적합
- 다양한 애드온, 대시보드, 멀티노드 등 실습에 편리한 기능 제공

### kind (Kubernetes IN Docker)
- Docker 컨테이너 위에 쿠버네티스 클러스터를 실행하는 도구
- 모든 노드(컨트롤 플레인, 워커)가 Docker 컨테이너로 동작
- CI/CD 환경, 빠른 테스트, GitHub Actions 등에서 많이 사용
- VM이 아닌 컨테이너 기반이므로 리소스 소모가 적고, 클러스터 생성/삭제가 매우 빠름
- 네트워크, 스토리지 등 실제 환경과 차이가 있을 수 있음

### multipass
- Canonical(우분투 개발사)에서 만든 경량 VM 관리 도구
- minikube, kind와 달리 쿠버네티스 전용이 아니라, 다양한 용도의 Ubuntu VM을 빠르게 생성/관리
- minikube, k3s, microk8s 등 쿠버네티스 환경을 multipass 위에 올려서 사용할 수 있음
- macOS, Windows, Linux에서 동일한 방식으로 VM 관리 가능

### lima (Linux Machines)
- macOS에서 리눅스 VM을 쉽게 실행할 수 있게 해주는 도구
- Docker Desktop 없이도 컨테이너, 쿠버네티스 환경을 구축할 수 있음
- nerdctl, k3s, rancher 등과 연동해 개발 환경 구성에 활용
- Lima 위에 kind, minikube, k3s 등 다양한 쿠버네티스 환경을 올릴 수 있음

### 요약 비교
| 도구        | 목적/특징                              | 쿠버네티스 전용 | 실행 방식         |
|-------------|----------------------------------------|----------------|------------------|
| minikube    | 로컬 쿠버네티스, 다양한 드라이버 지원   | O              | VM/컨테이너      |
| kind        | Docker 기반 쿠버네티스, 빠른 테스트     | O              | Docker 컨테이너  |
| multipass   | 경량 Ubuntu VM 관리                    | X              | VM               |
| lima        | macOS 리눅스 VM, 컨테이너 개발환경      | X              | VM               |

## multipass
---
### multipass 란
```
Mac 하드웨어 (Apple Silicon, EL0/EL1/EL2/EL3)
│
├─ EL2: Apple 하이퍼바이저  ←── Hypervisor.framework가 여기 접근권을 유저에 열어줌
│                                (게스트 CPU를 물리코어에서 네이티브 실행 + 메모리 가상화)
│
└─ macOS 커널 XNU (EL1)
   ├─ vmnet.framework ─── 가상 스위치 / NAT / DHCP(bootpd)
   │     └─ bridge100 (기본망, 192.168.64.0/24, 항상 NAT, VM 관리용)
   │            └─ member: vmenet0 (VM ↔ 스위치 연결)
   │
   ├─ en0 (실제 Wi-Fi, 192.168.0.122) ──→ 공유기(192.168.0.1) ──→ 인터넷
   │        ▲
   │        └─ [BRIDGE 모드일 때만] vmnet이 여기에 브리지로 얹어 VM NIC2 생성
   │
   └─ 유저스페이스
      ├─ multipassd (root 데몬) ── VM 생성/삭제/상태
      │
      ├─ qemu-system-aarch64 [controlplane]   ← 프로세스 1개 = VM 1대
      │   ├─ (CPU/메모리 → Hypervisor.framework 호출)
      │   ├─ (디스크 → virtio-blk → Mac 이미지파일)
      │   └─ 게스트 Ubuntu
      │       ├─ enp0s1  → bridge100(192.168.64.x)  = 관리용 NIC1
      │       ├─ enp0s2  → 공유기(192.168.0.x)        = PRIMARY_IP, default gw ★ (BRIDGE 모드)
      │       └─ kubelet / kube-apiserver / containerd ...
      │
      ├─ qemu-system-aarch64 [node01]
      └─ qemu-system-aarch64 [node02]
```
- Canonical 이 만든 경량 VM 관리 도구

### kubelet cgroup driver 설정
Linux 에선 cgroup 을 사용해 프로세스(컨테이너)마다 할당할 리소스를 제한한다. kubelet 과 container runtime 은 cgroup driver 를 통해 cgroup 을 사용하여 파드와 컨테이너의 리소스를 제한한다. 때문에 kubelet 과 container runtime 은 동일한 cgroup driver 를 가져야한다.

cgroup driver 의 종류는 아래와 같다.
- `cgroupfs`
- `systemd`

```sh
ps -p 1  # PID 1 이 systemd 인지 확인
```

kubelet 의 기본 cgroup 드라이버는 `cgroupfs` 드라이버이다. 리눅스 배포판의 init 시스템이 `systemd` 인 경우, init 프로세스는 root control group(`cgroup`)을 생성 및 사용하는 cgroup 관리자로 작동하기 때문에 cgroup 드라이버 역시 `systemd` 로 사용해야 한다. `systemd` 를 cgroup 드라이버로 사용하려면, `KubeletConfiguration` 의 `cgroupDriver` 옵션을 `systemd` 로 설정해야 한다. v1.22 이후 버전부터 kubeadm 으로 클러스터를 생성할 경우 사용자가 `KubeletConfiguration` 하위의 `cgroupDriver` 필드를 설정하지 않아도 kubeadm 이 기본값으로 `systemd` 를 사용한다.

### containerd cgroup driver 설정
`systemd` 를 kubelet 의 cgroup 드라이버로 구성했다면, 반드시 컨테이너 런타임의 cgroup 드라이버 또한 `systemd` 로 설정해야 한다. `runc` 와 함께 `/etc/containerd/config.toml` 에서 `systemd` cgroup 드라이버를 사용하려면, 사용 중인 containerd 버전에 따라 다음과 같이 설정한다.

Containerd 1.x 버전:
```sh
[plugins."io.containerd.grpc.v1.cri".containerd.runtimes.runc]
  ...
  [plugins."io.containerd.grpc.v1.cri".containerd.runtimes.runc.options]
    SystemdCgroup = true
```

Containerd 2.x 버전:
```sh
[plugins.'io.containerd.cri.v1.runtime'.containerd.runtimes.runc]
  ...
  [plugins.'io.containerd.cri.v1.runtime'.containerd.runtimes.runc.options]
    SystemdCgroup = true
```

[cgroup v2](https://kubernetes.io/ko/docs/concepts/architecture/cgroups/) 를 사용할 경우 `systemd` cgroup 드라이버가 권장된다.

```sh
sudo mkdir -p /etc/containerd
containerd config default \
  | sed 's/SystemdCgroup = false/SystemdCgroup = true/' \
  | sudo tee /etc/containerd/config.toml
sudo systemctl restart containerd
```

`containderd config default` 명령어는 containerd 의 기본 config.toml 을 추력한다. 기본 출력을 `| sed 's/SystemdCgroup = false/SystemdCgroup = true/'` 에 넘겨 `systemd` cgroup 드라이버를 사용하도록 수정하고 `| sudo tee /etc/containerd/config.toml` 로 설정파일 경로에 저장한다.

kubeadm init 으로 생성된 `/etc/kubernetes/admin.conf` 을 사용하여 `kubectl` 을 통해 `kube-apiserver` 와 통신할 수 있다.

### CNI 설치
